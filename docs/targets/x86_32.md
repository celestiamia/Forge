# x86_32 Linux (ELF32, i686)

32-bit Linux target for compatibility with older systems.

## Target Triple

```
x86_32-unknown-linux-gnu
```

Rust toolchain: `i686-unknown-linux-gnu`

## Build

```bash
# Add target
rustup target add i686-unknown-linux-gnu

# Install 32-bit libraries
sudo apt-get install gcc-multilib g++-multilib libc6-dev-i386

# Build compiler
cargo build --release --target i686-unknown-linux-gnu

# Compile program
./target/i686-unknown-linux-gnu/release/forgec input.dev -o output --target x86_32-unknown-linux-gnu
```

## Architecture Details

| Property | Value |
|----------|-------|
| Architecture | i686 (Pentium Pro+) |
| Format | ELF32 |
| Endianness | Little |
| Pointer Size | 32-bit |
| Page Size | 4 KiB |
| Calling Convention | cdecl |

## Registers

| Register | Purpose | Saved |
|----------|---------|-------|
| EAX | Return value | Volatile |
| EBX | Callee-saved | Preserved |
| ECX | Volatile | Volatile |
| EDX | Return high / volatile | Volatile |
| ESI | Callee-saved | Preserved |
| EDI | Callee-saved | Preserved |
| EBP | Frame pointer | Preserved |
| ESP | Stack pointer | Preserved |

## Calling Convention (cdecl)

- Args pushed right-to-left on stack
- Caller cleans stack
- Return value in EAX (EDX:EAX for 64-bit)
- Stack 4-byte aligned
- Struct returns use the i386 **sret** convention: a hidden first argument
  (caller-allocated struct pointer) receives the result; named parameters
  shift up by one 4-byte slot
- Struct arguments pass the struct's address (full value accessible to the
  callee)

## Syscalls

Linux syscalls via `int 0x80`:

| Syscall | EAX | EBX | ECX | EDX | ESI | EDI |
|---------|-----|-----|-----|-----|-----|-----|
| read | 3 | fd | buf | count | - | - |
| write | 4 | fd | buf | count | - | - |
| exit | 1 | code | - | - | - | - |
| mmap | 90 | addr | len | prot | flags | fd |
| socket | 359 | domain | type | protocol | - | - |

## Object Format

ELF32 with sections:
- `.text` - Code
- `.rodata` - Read-only data
- `.data` - Initialized data
- `.bss` - Zero-initialized

## Limitations vs x86_64

| Feature | x86_64 | x86_32 |
|---------|--------|--------|
| Pointer size | 64-bit | 32-bit |
| Registers | 16 GP | 8 GP |
| Float support | ✅ SSE2/x87 | ❌ Not implemented |
| GC | ✅ | ❌ (importing `std.gc` is a clean codegen error) |
| Register args | 6 in regs | 0 (all stack) |
| Red zone | 128 bytes | ❌ |
| Syscall ABI | `syscall` | `int 0x80` |

## Standard Library

| Module | Support |
|--------|---------|
| `std.io` | ✅ |
| `std.mem` | ✅ |
| `std.string` | ✅ |
| `std.math` | ✅ (int only) |
| `std.alloc` | ✅ (free-list, 4-byte headers; no GC) |
| `std.fmt` | ✅ |
| `std.volatile` | ✅ |
| `std.gc` | ❌ (clean codegen error) |

## Float Emulation

Not implemented. Float operations not available on x86_32 target.

Workaround: Use fixed-point arithmetic or compile for x86_64.

## Code Generation

- No SSE2 (baseline i686)
- x87 FPU not used (no float support)
- All integer ops use 32-bit registers
- Stack alignment: 4 bytes (not 16)

## Build Requirements

```bash
# Ubuntu/Debian
sudo apt-get install gcc-multilib g++-multilib libc6-dev-i386

# Fedora/RHEL
sudo dnf install glibc-devel.i686 libstdc++-devel.i686

# Arch
pacman -S gcc-multilib
```

## Performance

- Native 32-bit speed
- No 64-bit overhead
- Stack-only calling convention (slower than register args)
- No float hardware acceleration

## Compatibility

Runs on:
- Any x86_64 kernel with 32-bit support (CONFIG_IA32_EMULATION)
- Native 32-bit kernels
- Most 32-bit Linux distributions

Not compatible with:
- Systems without 32-bit userspace support
- Pure 64-bit kernels (no IA32 emulation)
